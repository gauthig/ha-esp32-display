# Installation Guide

## Prerequisites

- **ESP-IDF v5.3+** installed at `C:\esp\esp-idf`
  (tested with v5.5.5; activate with `. C:\esp\esp-idf\export.ps1`)
- **Python** in the ESP-IDF virtualenv (installed automatically with ESP-IDF)
- **esptool** (included with ESP-IDF)
- **Windows PowerShell** (the flash script is `.ps1`)
- **USB driver** for CH343P/CH340 (Waveshare board UART chip)

## Hardware: non-B vs B

This project targets the **non-B** board. The two look identical but differ:

| Feature | non-B (this project) | B variant (firefly-touch) |
|---------|----------------------|--------------------------|
| Backlight | LEDC PWM on GPIO 2 | CH422G IO expander |
| Reset lines | Hardware POR (GPIO_NUM_NC) | Routed through CH422G |
| USB-C | UART (CH343P) + native USB | Same |

Using B-variant firmware on non-B (or vice versa) will produce a black screen.

## USB ports on the board

The board has **two USB-C ports**:

| Port | Chip | Use |
|------|------|-----|
| UART USB-C (marked "UART") | CH343P → COM port | Flash and serial monitor |
| Native USB-C (marked "USB") | ESP32-S3 internal | Not used in this project |

**Always use the UART port for flashing and monitoring.** The native USB port
re-enumerates on every reboot, causing the monitor to miss early boot messages.

## 1. Clone the repo

```powershell
git clone https://github.com/youruser/ha-energy-display
cd ha-energy-display
```

## 2. Create a device config

The file `main/device_config.h` is gitignored — it is the "active" config
generated by `tools/flash-device.ps1`. You do not create it manually.

Instead, edit the device config for the board you want to flash:

```
devices/main_house/device_config.h
```

See the [Configuring a device](#configuring-a-device) section below.

## 3. Create secrets.h

`secrets.h` holds your WiFi credentials and Home Assistant token.
**It is gitignored and must never be committed.**

```powershell
copy devices\main_house\secrets.h.example devices\main_house\secrets.h
```

Edit `devices\main_house\secrets.h`:

```c
#pragma once

#define WIFI_SSID     "your_network_name"
#define WIFI_PASSWORD "your_wifi_password"

// Home Assistant → Profile → Long-Lived Access Tokens → Create Token
#define HA_TOKEN      "eyJhbGci..."
```

### Verify secrets.h is ignored

Check `.gitignore` contains:

```
devices/*/secrets.h
main/secrets.h
main/device_config.h
```

To confirm the file won't be committed:

```powershell
git status devices/main_house/secrets.h
# Expected output: nothing (file is ignored)
```

## 4. Build and flash

```powershell
.\tools\flash-device.ps1 -Device main_house -Port COM9
```

The script will:

1. Copy `devices/main_house/device_config.h` → `main/device_config.h`
2. Copy `devices/main_house/secrets.h` → `main/secrets.h` (if present)
3. Activate ESP-IDF and run `idf.py build`
4. Prompt you to put the device in boot mode
5. Flash with `esptool`

### Entering boot mode

The ESP32-S3 must be in download mode before flashing:

1. Hold the **BOOT** button (GPIO0)
2. Tap the **RESET** (RST/EN) button
3. Release **BOOT**

The device is now waiting for the flash tool. Press **Enter** in the script
prompt and esptool will write the firmware.

After flashing finishes, press **RESET** once to boot normally.

### If you get PermissionError 13 on the COM port

Something else is holding the port (usually a stale monitor session):

```powershell
Stop-Process -Name python -Force -ErrorAction SilentlyContinue
```

Then retry the flash command.

## 5. Monitor serial output

```powershell
. C:\esp\esp-idf\export.ps1
idf.py -p COM9 monitor
```

Press **RESET** on the board to see the full boot sequence. Exit with `Ctrl+]`.

Expected boot log (first run):

```
I app_init: Project name: ha_esp32_display
I wifi: connected with ghome, ...
I main: WiFi connected
I main: SNTP started
I ha_client: grid 27.4 kWh | net 434 W | solar 215 W (0.2 kWh today)
```

## Configuring a device

All device-specific settings live in `devices/<name>/device_config.h`.

### Key fields

```c
#define DEVICE_NAME  "Main House"        // shown in UI status bar
#define HA_HOST      "192.168.1.54"      // your HA IP
#define HA_PORT      8123
#define LOCAL_TZ     "PST8PDT,M3.2.0,M11.1.0"  // POSIX TZ string

// Main energy sensor entity IDs (find in HA Developer Tools → States)
#define ENT_GRID_KWH    "sensor.mainsfromgrid_energy_today"
#define ENT_SOLAR_W     "sensor.solar_line_1_power_minute_average"
// ... (see template for all 6)

// Circuit count and names
#define HA_NUM_CIRCUITS  13
#define CIRCUIT_NAMES_INIT   "Pool", "A/C", "Oven", ...
#define CIRCUIT_ENTITIES_TEMPLATE \
    "{{ states('sensor.pool_power_minute_average') }}|" \
    ...
```

### No solar?

Set these three macros to point at your total consumption sensor:

```c
#define ENT_SOLAR_W   ENT_TOTAL_W
#define ENT_SOLAR_KWH "sensor.dummy_kwh"   // or a zeroed helper
#define ENT_NET_W     ENT_TOTAL_W
```

### Finding entity IDs

In Home Assistant: **Developer Tools → States** → search for your sensor name.
Emporia Vue circuits end in `_power_minute_average`. The exact name depends on
what your Emporia devices were named during setup.

### Timezone strings

| Location | TZ string |
|----------|-----------|
| US Pacific | `PST8PDT,M3.2.0,M11.1.0` |
| US Mountain | `MST7MDT,M3.2.0,M11.1.0` |
| US Central | `CST6CDT,M3.2.0,M11.1.0` |
| US Eastern | `EST5EDT,M3.2.0,M11.1.0` |

## Adding a new device

1. Copy the template:
   ```powershell
   Copy-Item -Recurse devices\NEW_DEVICE_TEMPLATE devices\my_garage
   ```

2. Edit `devices\my_garage\device_config.h` — change all the TODOs.

3. Create secrets:
   ```powershell
   copy devices\my_garage\secrets.h.example devices\my_garage\secrets.h
   # Edit with WiFi and HA token
   ```

4. Update `devices\my_garage\INFO.md` with location, COM port, and circuit table.

5. Build and flash:
   ```powershell
   .\tools\flash-device.ps1 -Device my_garage -Port COM12
   ```

## Partition table note

The firmware is ~1.5 MB. The project uses a custom partition table
(`partitions.csv`) with a 2 MB factory slot. The default ESP-IDF 1 MB
partition **will not work** — do not delete `partitions.csv` or remove
`CONFIG_PARTITION_TABLE_CUSTOM=y` from `sdkconfig.defaults`.
